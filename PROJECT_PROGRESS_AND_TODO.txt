1. PROJECT OVERVIEW & SCOPE
--------------------------------------------------------------------------------
This project implements the core hardware protocol and scheduling architecture
proposed in the ComPASS paper across two state-of-the-art open-source simulators:
  1. Samsung PIMSimulator (System/DRAM cycle-level simulator for PIM architectures)
  2. Ramulator (Cycle-accurate DRAM simulator with out-of-order CPU core models)

Explicit Inclusions:
  - PIM-ACT command implementation with optype field encoding in Samsung PIMSimulator.
  - Multi-bank simultaneous activation and PIM operation execution.
  - Four PIM-ACT microbenchmark kernels (GEMV, ADD, MUL, ReLU) with golden verification.
  - JEDEC-compliant LPDDR5-6400 DRAM model (4 channels, 2 ranks, 2 KB row size, 16 banks).
  - Out-of-order 16-core CPU configuration with SPEC CPU memory trace support.
  - Embedded PIM Request Generator: 32-entry macro-request buffer, 4 KB data buffer.
  - Separate 2-entry PIM queue alongside 64-entry host read/write queues.
  - Three memory scheduling policies:
      a. FR-FCFS (First-Ready First-Come First-Served across host & PIM streams)
      b. Batch Scheduling (PAR-BS with default batch size 64)
      c. Proposed Throughput Balancer:
           * ST-BLC (Static Balancer: alternating P=64, N=64, row-conflict PREA hiding)
           * AT-BLC (Adaptive Balancer: dynamic N in [16, 128] adjusted per tREFI)
  - Quantitative evaluation reporting Host Slowdown and PIM Throughput.

Explicit Exclusions (as requested):
  - SK hynix AiM simulator.
  - End-to-end full language-model (LLM) serving evaluations.

2. LPDDR5-6400 DRAM Model:
   - Files: ramulator/src/LPDDR5.h & ramulator/src/LPDDR5.cpp
     * Implemented JEDEC-compliant LPDDR5 standard at 6400 MT/s:
         - Operating frequency: 3200 MHz (tCK = 0.3125 ns).
         - Width: 16-bit channel, Burst Length: BL16 (32 Byte access granularity).
         - Row buffer size: 2 KB (1024 columns x 16-bit).
         - Organization: 8Gb per die, 16 banks (4 bank groups x 4 banks).
         - Timing parameters: nRCD=18, nRP=18, nRAS=42, nRC=60, nRTP=8, nWR=34,
           nWTR_S=10, nWTR_L=14, nFAW=16, nRRD=4, nRFC=140, nREFI=12480.
   - Files: ramulator/src/Main.cpp & ramulator/src/MemoryFactory.cpp
     * Wired LPDDR5 standard option and factory instantiation.

3. Memory Controller & PIM Request Generator:
   - File: ramulator/src/Controller.h
     * Added dedicated 2-entry PIM queue: `Queue pim_q` (`pim_q.max = 2`).
     * Host queues configured: `readq.max = 64`, `writeq.max = 64`.
     * Added `PIMRequestGenerator` struct:
         - 32-entry macro-request buffer.
         - 4 KB channel data buffer.
         - Automatically decomposes high-level GEMV operations into micro-requests
           and injects them into `pim_q` when space allows.

4. Scheduling Policies:
   - File: ramulator/src/Controller.h
     * Policy 1 (FR-FCFS):
         - Evaluates row-hits across both host and PIM queues.
         - Strictly prioritizes ready row-hits to maximize row buffer locality and
           minimize PREA/PIM-ACT turnaround penalties.
     * Policy 2 (BATCH / PAR-BS):
         - Groups incoming requests into batches of size 64 (`batch_size = 64`).
         - Requests marked with current `batch_id`.
         - Highest priority given to older batch requests; within a batch, prioritized
           via FR-FCFS.
     * Policy 3 (Proposed Throughput Balancer - ST-BLC & AT-BLC):
         - ST-BLC: Alternates priority turns between PIM stream (P = 64 commands)
           and Host stream (N = 64 commands).
         - Turn-switching optimization: Automatically switches turn early if queue is
           empty or if PIM encounters a row conflict (allowing PREA latency to be
           overlapped while servicing host requests).
         - AT-BLC: At every refresh interval (tREFI), measures real-time PIM progress
           against target progress (T' = 0.90 * T). Dynamically adjusts host turn
           quota N in [16, 128] to ensure PIM meets target completion without starving host.

5. Statistics & Metrics Tracking:
   - Added controller stats:
       - `pim_requests_served`, `host_requests_served`
       - `pim_transaction_bytes`
       - `pim_row_hits`, `pim_row_misses`, `pim_row_conflicts`
       - Host IPC and CPU cycles recorded per core.
